Architecture

RouteMaker is a web app backed by one server. A weekly rebuild turns OpenStreetMap and public agency data into a rated road network and routing graphs; the app server plans routes on them and adds live data such as closures, bikeshare and transit. Everything is open source[1].

At a glance

  • Front end: React and MapLibre in the browser, installable as an app, plus a thin Android shell.
  • Back end: Django on PostgreSQL with PostGIS, Valhalla for routing, Photon for place search, all behind one Caddy web server.
  • Data: rebuilt weekly from OpenStreetMap and agency data; live feeds read every few minutes.
  • Privacy: signed-out plans are never stored; sign-in is through Discord and keeps no Discord token.

Looking for something else? How roads are rated: Stress ratings. Planning from Claude or another assistant: AI assistants. Every data source and licence: Acknowledgements.

The running system

More: The running system
  • Web server: Caddy[12] handles encryption, serves the app's files and the map archives, and passes everything else to the app server. It refuses to be framed by other sites and sends a strict content security policy.
  • App server: Django and Django Ninja[10], the planning API, accounts, saved and shared routes, and the stress tiles.
  • Routers: one Valhalla[2] process per graph variant (below).
  • Database: PostgreSQL with PostGIS[6]: every rated road segment, accounts, saved routes, closures and the job queue.
  • Background worker: Procrastinate[11], a job queue kept in the same database, for closures, feeds, alerts on saved routes and backups.
  • Place search: a self-hosted Photon[13] index of the region, so searches never leave the server.

The weekly rebuild

More: The weekly rebuild

The rebuild downloads OpenStreetMap extracts[3], merges and clips them to the coverage area with Osmium[4], and converts USGS elevation[5] into the height files Valhalla reads. It then rates every road (see Which rating wins), writes the levels into the map data with a Lua script that Valhalla's graph builder runs, and builds each router graph. A new map goes live only after a report of every rating that changed, by county, has been checked; the old map is kept so a bad build can be rolled back.

The base map, contour lines, place search index and transit timetables are refreshed on their own, less often. Contours are drawn at 20, 40 and 100 ft [6, 12 and 30 m] from USGS 1/3 arc-second elevation with GDAL[14].

Planning a route

More: Planning a route

Each request has a time budget, a rate limit and a cap on plans in flight, so one busy rider cannot slow everyone else. Trips over about 19 mi [30 km] are refined leg by leg. A route can have 2 to 25 points; very long plans over 93 mi [150 km] ask for confirmation when signed out.

A plan's answer is kept for up to 10 minutes (not for Bikeshare or transit, whose answers are live), so asking for the same route again (Undo, or opening it again) is answered at once. On the beta server the app server's workers share these answers through a small memcached kept only in memory (16 MB of answers); if it is down or slow, the route is simply planned again. When you change a plan in Go after its first route is shown but while its full plan is still being worked out, the app cancels that full plan (/api/route/cancel): the server stops it at its next call to the router, and the new plan goes without waiting for it to finish.

Apps, accounts and AI assistants

RouteMaker installs as an app, has a thin Android shell for rides, signs in through Discord without keeping a token, and keeps your data only when you ask it to.

More: Apps, accounts and AI assistants
  • Installable app. The site installs as an app. Its service worker keeps the app's own files for offline starts but never caches routes, tiles or account data unless you choose Keep for offline on a planned route (up to 10).
  • Android app. A thin Capacitor[15] shell around the site that adds background location, a screen wake lock and spoken cues during a ride, and, from its next update, Android's own share sheet for sharing a route or ride.
  • Accounts. Sign-in uses Discord with the narrowest permission (your user id). RouteMaker exchanges the sign-in code once and keeps no Discord token.
  • Garmin and Wahoo. When you connect Garmin or Wahoo in Settings, the server keeps that service's sign-in token, encrypted under a key that is never in the database. It contacts Garmin (diauth.garmin.com to sign in and renew the token, apis.garmin.com for the rest) or api.wahooligan.com only to send the routes you choose, read your account number once, and end the connection when you disconnect or delete your account. Deleting your account also removes from Wahoo up to 100 routes RouteMaker sent there.
  • Weather. For the weather along a route, your browser sends this server a few points on the line still to ride or, in Roam, where you are. The server rounds each to 0.01 degree, about 0.7 mi [1.1 km], and asks api.weather.gov (the National Weather Service's alerts) and api.open-meteo.com (Open-Meteo's rain forecast) about the rounded points, so they see this server, never you. It keeps the answers 2 minutes in memory, logs no point and writes nothing.
  • Featured routes. Each post, at /routes/ and its name, is a page the server makes whole, so it reads without JavaScript and link previews see it; a script, /post.js, then draws the live map and charts and turns on Send to Garmin and Send to Wahoo. A post's route is copied when it is written and kept permanently, owned by no account; a route that starts, ends or stops near its author's Home is refused. For a post's link picture, an admin's browser draws the post's map at 1200 by 630 pixels and sends it to the server. Nothing about the reader is kept: the pages are the same for every reader.
  • Sharing. A shared route stores the exact line under a random link, kept for a year after it was last opened. Where the route starts, ends or stops near Home, its preview image leaves out the route and pins inside Home's circle and keeps the map there.
  • AI assistants. RouteMaker has a Model Context Protocol[16] server, so an AI assistant can find places and plan and revise routes. Through the site's connector, after you sign in, it can save routes to your account, and Settings lists each connected assistant with a Disconnect button; instance admins can also have it draft Featured routes posts. Run on your own computer, the server plans and writes GPX files only. See AI assistants.

Accessibility and testing

Accessibility is a requirement: WCAG 2.2 AA outside the map and a non-map way to do everything. Thousands of automated tests and reference routes guard each release.

More: Accessibility and testing
  • Accessibility is a requirement, not an extra: WCAG 2.2 AA[17] for everything outside the map canvas, nothing shown by colour alone, and a non-map way to do every route-shaping action. Screen-reader users and blind stokers on tandems are part of the intended audience. Accessibility mode adds keyboard map tools.
  • Tests: thousands of Python tests run against a real PostGIS database, frontend tests run in Node, and a browser check drives the app in Chromium for focus order, contrast and screen-reader names. Reference routes are the quality bar for routing changes.
  • Releases ship on release branches, are tested as a whole, and are tagged. Each release has short rider-facing notes.
